# Etapa 7.2: o modelo de impressão neutro e o DANFCE

**Branch:** `fase-7-impressao`. **Pré-requisito:** a 7.1 feita e commitada. **Regras comuns:** `docs/etapas/00-COMUM.md`.

**Objetivo:** definir no núcleo o **modelo de impressão neutro** (`PROJETO.md` 10.1: blocos de texto com alinhamento e destaque, o QR Code, o código de barras, imagem de 1 bit, e as seções e tabelas que o DANFE vai precisar) e montar no leiaute o **DANFCE** (a NFC-e impressa em bobina) a partir de uma NFC-e lida, **conferido contra o Manual de Padrões Técnicos do DANFE NFC-e e QR Code**. O PDV (ESC/POS) e o renderizador PDF (7.4) consomem o mesmo modelo. Esta etapa **não** gera PDF nem ESC/POS.

**Aprovado em 2026-10-24, todas as decisões abaixo pela recomendação.** O desenho do modelo é o centro desta etapa e a base da 7.3 e da 7.4: registre-o em `docs/CONTRATOS.md` **21** (próximo número livre; a 7.1 usou a 20 se teve API pública) com os tipos **como implementados**. Você pode ajustar nomes e membros durante a implementação desde que (a) respeite as decisões, (b) as 7.3 e 7.4 continuem possíveis e (c) registre o que mudou em "Ajustes ao desenho".

## O modelo neutro (no núcleo: `src/OpenDFe.Nucleo/Impressao/`, namespace `OpenDFe.Impressao`)

Tipos **imutáveis**, públicos, sem lógica de renderização, seguros em paralelo. Construtores validam os argumentos (`ArgumentException`). Documentação XML em todos. Nomes sem preposição.

```csharp
/// O documento de impressão: o papel e a lista de elementos, de cima para baixo.
public sealed class DocumentoImpressao
{
    public DocumentoImpressao(PapelImpressao papel, IReadOnlyList<ElementoImpressao> elementos);   // cópia da lista
    public PapelImpressao Papel { get; }
    public IReadOnlyList<ElementoImpressao> Elementos { get; }
    public string? Titulo { get; init; }             // metadado (título do PDF)
}

/// O papel. Fábricas estáticas; construtor interno.
public sealed class PapelImpressao
{
    public static PapelImpressao Bobina80 { get; }   // 80 mm, 48 colunas de caracteres (fonte A, 12 pontos de largura a 203 dpi)
    public static PapelImpressao Bobina58 { get; }   // 58 mm, 32 colunas
    public static PapelImpressao A4Retrato { get; }  // 210 x 297 mm
    public static PapelImpressao A4Paisagem { get; }
    public TipoPapel Tipo { get; }                   // Bobina (altura contínua) ou Folha (altura fixa, várias páginas)
    public double LarguraMm { get; }
    public double? AlturaMm { get; }                 // nula na bobina
    public int Colunas { get; }                      // na bobina, as colunas de caracteres; na folha, 0
    public double MargemMm { get; }
}
public enum TipoPapel { Bobina, Folha }

public abstract class ElementoImpressao { private protected ElementoImpressao(); }   // fechado: só a lib deriva

/// Texto: quebrado pelo renderizador na largura do papel.
public sealed class TextoImpressao : ElementoImpressao
{
    public TextoImpressao(string texto);
    public string Texto { get; }                     // sem quebra de linha obrigatória; \n é quebra explícita
    public AlinhamentoImpressao Alinhamento { get; init; } = AlinhamentoImpressao.Esquerda;
    public bool Negrito { get; init; }
    public TamanhoTexto Tamanho { get; init; } = TamanhoTexto.Normal;      // Normal, Duplo (largura e altura), Pequeno
    public bool Invertido { get; init; }             // texto claro em fundo preto (destaque de título)
}
public enum AlinhamentoImpressao { Esquerda, Centro, Direita }
public enum TamanhoTexto { Pequeno, Normal, Duplo }

/// Uma linha de células com larguras proporcionais (os itens da NFC-e: código, descrição, quantidade...).
public sealed class LinhaImpressao : ElementoImpressao
{
    public LinhaImpressao(IReadOnlyList<CelulaImpressao> celulas);          // 1 ou mais
    public IReadOnlyList<CelulaImpressao> Celulas { get; }
    /// As larguras inteiras, em colunas, que somam exatamente `colunas` (maior resto): para o renderizador de texto.
    public IReadOnlyList<int> Larguras(int colunas);
}
public sealed class CelulaImpressao
{
    public CelulaImpressao(string texto, double peso = 1);                  // peso > 0
    public string Texto { get; }  public double Peso { get; }
    public AlinhamentoImpressao Alinhamento { get; init; }  public bool Negrito { get; init; }
}

public sealed class SeparadorImpressao : ElementoImpressao { public EstiloSeparador Estilo { get; init; } }   // Tracejado, Cheio
public sealed class EspacoImpressao : ElementoImpressao { public EspacoImpressao(int linhas); public int Linhas { get; } }

/// O QR Code. O renderizador desenha com correção de erro nível M (o manual) e UTF-8.
public sealed class QrCodeImpressao : ElementoImpressao
{
    public QrCodeImpressao(string texto);
    public string Texto { get; }
    public double LadoMm { get; init; } = 25;        // o manual: pelo menos 25 mm; confira
    public AlinhamentoImpressao Alinhamento { get; init; } = AlinhamentoImpressao.Centro;
}

/// Código de barras Code 128 conjunto C (a chave de acesso de 44 dígitos no DANFE).
public sealed class CodigoBarrasImpressao : ElementoImpressao
{
    public CodigoBarrasImpressao(string digitos);    // só dígitos, quantidade par
    public string Digitos { get; }  public double AlturaMm { get; init; } = 10;
}

/// A imagem de 1 bit (o logotipo do emitente e a assinatura do software emissor): a térmica só imprime preto.
public sealed class Imagem1Bit
{
    public Imagem1Bit(int largura, int altura, ReadOnlyMemory<byte> bits);  // bits empacotados, MSB primeiro, cada linha em bytes inteiros, 1 = preto
    public static Imagem1Bit Limiarizar(ReadOnlySpan<byte> cinza, int largura, int altura, byte limiar = 128);  // de 8 bits por pixel
    public int Largura { get; }  public int Altura { get; }  public ReadOnlyMemory<byte> Bits { get; }
    public bool Preto(int x, int y);
}
public sealed class ImagemImpressao : ElementoImpressao
{
    public ImagemImpressao(Imagem1Bit imagem);
    public Imagem1Bit Imagem { get; }  public AlinhamentoImpressao Alinhamento { get; init; } = AlinhamentoImpressao.Centro;
    public double? LarguraMm { get; init; }          // nula = tamanho natural a 203 dpi
}

/// DANFE (A4): uma seção com título e linhas de campos rotulados, em grade (7.3 usa; definida aqui porque o modelo é um só).
public sealed class SecaoImpressao : ElementoImpressao
{
    public SecaoImpressao(string? titulo, IReadOnlyList<LinhaCamposImpressao> linhas);
    public string? Titulo { get; }  public IReadOnlyList<LinhaCamposImpressao> Linhas { get; }
}
public sealed class LinhaCamposImpressao { public LinhaCamposImpressao(IReadOnlyList<CampoImpressao> campos); public IReadOnlyList<CampoImpressao> Campos { get; } }
public sealed class CampoImpressao
{
    public CampoImpressao(string rotulo, string valor, double peso = 1);
    public string Rotulo { get; }  public string Valor { get; }  public double Peso { get; }
    public AlinhamentoImpressao Alinhamento { get; init; }  public bool Negrito { get; init; }
}
/// DANFE (A4): tabela com cabeçalho repetido a cada página (os itens do DANFE, 7.3).
public sealed class TabelaImpressao : ElementoImpressao
{
    public TabelaImpressao(string? titulo, IReadOnlyList<ColunaImpressao> colunas, IReadOnlyList<IReadOnlyList<string>> linhas);
    public string? Titulo { get; }  public IReadOnlyList<ColunaImpressao> Colunas { get; }  public IReadOnlyList<IReadOnlyList<string>> Linhas { get; }
}
public sealed class ColunaImpressao { public ColunaImpressao(string titulo, double peso, AlinhamentoImpressao alinhamento = AlinhamentoImpressao.Esquerda); /* propriedades */ }
public sealed class QuebraPaginaImpressao : ElementoImpressao { }
```

**Decisões de desenho** (aprovadas): (1) o modelo mora no núcleo e **não conhece NF-e** (serve ao CT-e e ao MDF-e depois); (2) o texto é sempre `string` já formatado (data, dinheiro, CNPJ): quem monta o modelo (o leiaute) formata, quem renderiza só desenha; (3) o modelo é **estrutural**, sem fonte nem coordenada em pixel: o renderizador escolhe; (4) a lista de elementos é fechada por `private protected`; (5) para o texto da térmica, o modelo oferece `LinhaImpressao.Larguras(colunas)` e `TextoImpressao` ganha o método `Quebrar(int colunas)` (lista de linhas, quebrando em espaço, sem cortar palavra menor que a linha) para o PDV não reescrever isso; (6) `Imagem1Bit` valida o tamanho de `bits` (`ceil(largura/8) * altura`).

**Testes do modelo** (`Nucleo.Testes`, pasta `Impressao/`): cada construtor e recusa; `Larguras` somando exatamente `colunas` (propriedade: para pesos aleatórios com semente fixa e colunas de 1 a 100, a soma é `colunas` e nenhuma célula perde se `colunas ≥ células`); `Quebrar` (palavra maior que a linha, `\n`, linha vazia, acentos); `Imagem1Bit` (empacotamento, `Preto`, `Limiarizar`, largura 1 e 9, tamanho errado); imutabilidade (a lista passada não vira a do objeto); o conjunto fechado (não dá para derivar fora do assembly: use reflexão sobre o construtor `private protected`).

## O DANFCE (no leiaute: `src/OpenDFe.Leiaute.NFe.v400/Impressao/`, namespace `OpenDFe.NFe`)

```csharp
public sealed class OpcoesDanfce
{
    public PapelImpressao Papel { get; init; } = PapelImpressao.Bobina80;   // Bobina80 ou Bobina58; outro papel → ArgumentException
    public Imagem1Bit? Logotipo { get; init; }            // no topo
    public Imagem1Bit? AssinaturaSoftware { get; init; }  // no rodapé, a marca do software emissor (o PDV pede)
    public string? TextoRodape { get; init; }             // uma linha livre depois do QR Code (ex.: "ERP Core - DLA Tec")
    public ViaDanfce Via { get; init; } = ViaDanfce.Consumidor;   // Consumidor ou Estabelecimento (contingência: duas vias)
}
public enum ViaDanfce { Consumidor, Estabelecimento }

public sealed class LeiauteNFe400
{
    /// Monta o DANFCE de uma NFC-e lida (o nfeProc autorizado ou o NFe assinado em contingência, sem protocolo).
    /// ArgumentException: a nota não é NFC-e (modelo 65), não tem chave, ou não tem o QR Code (Suplementares.QrCode) e a
    /// URL de consulta (a NFC-e sem eles não é imprimível). Não confere regras do MOC nem o schema.
    public DocumentoImpressao Danfce(NotaLida nota, OpcoesDanfce? opcoes = null);
}
```

**Conteúdo e ordem**: exatamente as seções do Manual (item do DANFE NFC-e), na ordem dele, com os rótulos e o texto fixo dele. Lista de partida (a confirmar contra o manual; **o manual vence**): cabeçalho do emitente (CNPJ, razão social, nome fantasia se houver, endereço completo; o logotipo antes), título "DANFE NFC-e - Documento Auxiliar da Nota Fiscal de Consumidor Eletrônica" (e "Não permite aproveitamento de crédito de ICMS"), a mensagem do ambiente de homologação ("EMITIDA EM AMBIENTE DE HOMOLOGAÇÃO - SEM VALOR FISCAL") quando `tpAmb` 2, os itens (código, descrição, quantidade, unidade, valor unitário, valor total, com a quebra da descrição longa), os totais (quantidade total de itens, valor total, desconto, acréscimos/frete, valor a pagar), as formas de pagamento (descrição do `tPag`, valor pago, troco), a informação dos tributos totais (Lei 12.741, `vTotTrib`, só quando informado), o consumidor (CPF/CNPJ/ID estrangeiro/nome, ou "CONSUMIDOR NÃO IDENTIFICADO"; o endereço na entrega em domicílio), a área de mensagem fiscal (número, série, data de emissão, via, o protocolo e a data da autorização quando houver, a URL de consulta, a chave em grupos de 4, o QR Code), as informações adicionais (`infCpl`), a legenda de contingência (**"EMITIDA EM CONTINGÊNCIA"** e **"Pendente de autorização"** quando `tpEmis` 9 e sem protocolo; com protocolo, só o protocolo) e as duas vias (Consumidor e Estabelecimento) exigidas na contingência — a escolha da via é da `OpcoesDanfce.Via`; **a lib não decide quantas vias imprimir**. Itens cancelados ou NFC-e cancelada: o DANFCE de nota cancelada não se imprime; não trate (a situação diz).

**Formatação** (pt-BR sem depender da cultura do sistema, que no Linux enxuto pode faltar): dinheiro `1.234,56`, quantidades com as casas da nota (até 4) sem zeros sobrando à direita além do mínimo que o manual pedir, datas `dd/MM/yyyy HH:mm:ss` no fuso e com a hora que a nota traz (**sem converter**), CNPJ `00.000.000/0000-00`, CPF `000.000.000-00`, chave em grupos de 4 separados por espaço. Escreva um formatador interno (`FormatadorImpressao`; **não** `FormatoImpressao`, que já é o enum do `tpImp`) com `NumberFormatInfo` explícito e testes; não use `CultureInfo("pt-BR")`.

**Fonte dos dados**: a `NotaLida.Nota` (identificação, emitente, destinatário, itens, totais, pagamento, informações adicionais, suplementares), `NotaLida.Protocolo`, `NotaLida.Chave`. O que o DANFCE precisa e a leitura não traz fica no registro da situação como "lacuna do modelo".

## Testes do DANFCE (`NFe.Testes`, pasta `Impressao/`)

- **Golden files de texto.** Um renderizador **só de teste** (`TextoPlano`, interno ao projeto de teste) converte o `DocumentoImpressao` da bobina de 48 colunas em texto puro (alinhamento, quebra, colunas pelo `Larguras`, separador, `[QR: ...]`, `[IMAGEM 120x40]`). Compare com os arquivos `tests/OpenDFe.NFe.Testes/Impressao/Esperado/*.txt` (versionados). **Você gera os arquivos, mas só depois de conferi-los linha a linha contra o manual** (e anota na situação "golden conferidos contra o manual"); um teste que falha por diferença de golden imprime o texto novo para facilitar a revisão. Casos: 1 item à vista em dinheiro com troco; 5 itens com desconto e acréscimo; cartão de crédito e dinheiro juntos; consumidor com CPF, com CNPJ, estrangeiro, sem identificação; entrega em domicílio (indPres 4) com o endereço; homologação; autorizada com protocolo; **contingência offline sem protocolo** (as duas vias, `Via` = Consumidor e Estabelecimento); `vTotTrib` presente e ausente; descrição longa e `infCpl` longo (quebras); papel de 58 mm; com logotipo e com assinatura do software; quantidade fracionada (3 casas), valores com milhar; nome com acento.
- **Validação do conteúdo, independente do golden:** testes que olham o modelo (não o texto): o QR Code do modelo **é** o `Suplementares.QrCode` (igual, byte a byte); a URL de consulta; a chave sem espaços tem 44 dígitos e é a da nota; os totais batem com `vNF`; a soma dos itens exibidos; a quantidade de itens; a ordem das seções.
- **Entrada de verdade:** uma NFC-e produzida pelo próprio fluxo da lib (a nota do modelo → `Preparar`/autorização contra o emulador → `XmlProcessado` → `Ler` → `Danfce`), em `DanfceEmuladoTestes` (SEFAZ emulada, certificado autoassinado), e uma offline da 5.2 (preparada → `Ler` → `Danfce`, sem protocolo). É o teste de que o QR Code que a 5.1/5.2 gera é o que o DANFCE imprime.
- **Recusas:** NF-e (modelo 55), sem chave, sem QR Code, papel A4.
- **Mutação provada:** tirar a legenda de contingência; trocar o `vNF` por `vProd`; imprimir a hora convertida para UTC.
