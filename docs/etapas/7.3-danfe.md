## Decisões (todas aprovadas pela recomendação)

1. **Escopo:** o DANFE **retrato (`tpImp` 1) e paisagem (2)** completos. O **DANFE Simplificado (3, etiqueta)** e o **Simplificado Tipo 2 (6, NT 2026.002)** entram **se** o Anexo II/NT trouxer o leiaute de forma implementável (campos, ordem, dimensões); senão registre "não implementado: o leiaute não está nas fontes obtidas (qual fonte tentada)" na situação e no checklist. O DANFE da NFC-e é o DANFCE (7.2). `tpImp` 0 e 4/5 não geram DANFE de NF-e (`ArgumentException` com a razão).
2. **A API:**

```csharp
public sealed class OpcoesDanfe
{
    public Imagem1Bit? Logotipo { get; init; }              // no quadro do emitente
    public bool Canhoto { get; init; } = true;              // o canhoto destacável do retrato
    public OrientacaoDanfe? Orientacao { get; init; }       // null = pelo tpImp da nota (1 retrato, 2 paisagem)
    public bool Cancelada { get; init; }                    // marca d'água "CANCELADA" (a situação vem de quem usa: a consulta/evento)
    public string? TextoRodape { get; init; }               // ex.: "Impresso por ERP Core"
}
public enum OrientacaoDanfe { Retrato, Paisagem }

public sealed class LeiauteNFe400
{
    /// Monta o DANFE de uma NF-e lida (o nfeProc com o protocolo; sem protocolo, em contingência, sai com a legenda do Anexo II).
    /// ArgumentException: a nota não é NF-e (modelo 55), não tem chave, ou o tpImp pede outro documento.
    public DocumentoImpressao Danfe(NotaLida nota, OpcoesDanfe? opcoes = null);
}
```

3. **Acréscimos ao modelo neutro (núcleo), só os que o Anexo II exigir**, em versão menor (`PublicAPI.Unshipped`), documentados e testados no `Nucleo.Testes`; pelo menos:
   - `DocumentoImpressao.CabecalhoContinuacao` (`IReadOnlyList<ElementoImpressao>`, `init`): o que se repete no topo das páginas seguintes (o quadro do emitente resumido, a chave);
   - `DocumentoImpressao.MarcaAgua` (`string?`, `init`): o texto diagonal em todas as páginas (CANCELADA; SEM VALOR FISCAL em homologação);
   - **fichas de paginação** no texto de um `CampoImpressao`/`TextoImpressao`: o contrato do texto `{pagina}` e `{paginas}`, substituídos pelo renderizador (para "Folha 1/2"); documente e teste o `Substituir` (um método utilitário público no modelo: `TextoPaginado.Resolver(texto, pagina, paginas)`);
   - `TabelaImpressao`: se o Anexo II mandar um comportamento de quebra que o modelo da 7.2 não expressa (linha que não pode ser dividida entre páginas, cabeçalho repetido), acrescente a opção.
   Cada acréscimo é opcional para os renderizadores: um renderizador que ignora `MarcaAgua` ainda gera um documento válido.
4. **Formatação:** o formatador da 7.2 (pt-BR explícito, sem a cultura do sistema), acrescentando o que o Anexo II pedir (alíquotas com 2 casas, quantidades/valores unitários com as casas da nota até 4 ou 10, NCM com 8 dígitos, CFOP, `O/CST` = origem + CST ou CSOSN, CEP `00000-000`, telefone, chave em grupos de 4 no texto, 44 dígitos no código de barras).
5. **O código de barras** é o `CodigoBarrasImpressao` com os 44 dígitos da chave; a imagem do logotipo, a `Imagem1Bit`; o QR Code só no Tipo 2 (se implementado).
6. **Sem regra de validação nova:** o DANFE imprime o que a nota tem; não confere o MOC (a escrita e as regras de antes de transmitir já conferiram). O que o Anexo II exige e a leitura não entrega vai para "lacunas do modelo" na situação.

4. Testes, documentação, situação.

## Testes

- **Golden de estrutura** (renderizador de texto de teste da 7.2 estendido para seções, campos e tabelas: `ROTULO: valor` em grade; páginas não, que a paginação é do renderizador): NF-e simples (1 item, ICMS Simples), com ICMS normal e ST, com IPI, com ISSQN (serviço), com duplicatas (cobrança), com transportador e volumes, com local de retirada e de entrega, destinatário estrangeiro e CPF, com `infAdProd`, com 60 itens (a tabela inteira no modelo), exportação, com IBS/CBS (se o Anexo II os mostra), contingência (sem protocolo, com a legenda), homologação (marca d'água), cancelada (opção), retrato e paisagem. **Conferidos linha a linha contra o Anexo II** antes de versionados (anote "golden conferidos").
- **Conteúdo independente do golden:** a chave do código de barras é a da nota e tem 44 dígitos; o protocolo e a data; os totais exibidos são os do `Total`; a soma dos itens bate; `tpNF` 0/1 com o texto do manual; a ordem dos quadros é a do Anexo II; o `CabecalhoContinuacao` presente.
- **Entrada real:** a NF-e autorizada contra a SEFAZ emulada (`XmlProcessado` → `Ler` → `Danfe`), em `DanfeEmuladoTestes`; o `tests/Exemplos/erpcore-nfeproc-entrada.xml` (uma NF-e de verdade com os dados trocados) → `Danfe` sem exceção e com os campos certos.
- **Recusas:** NFC-e, `tpImp` 0, 4 e 5, sem chave.
- **Mutação provada:** o `O/CST` sem a origem; a chave com um dígito a menos; o `tpNF` trocado; o quadro do emitente fora de ordem.
