## Decisões (todas aprovadas pela recomendação)

1. **`CancelamentoSubstituicao`** (nome sem preposição; o `PROJETO.md` escreve `CancelamentoPorSubstituicao`, já corrigido na 6.1):

```csharp
/// O cancelamento por substituição (110112) de uma NFC-e: cancela a NFC-e e aponta a que a substitui.
public sealed class CancelamentoSubstituicao : Evento
{
    /// ArgumentNullException: chave nula. ArgumentException: alguma das chaves que não é de NFC-e (modelo 65), as duas
    /// iguais, protocolo que não tem 15 dígitos, justificativa nula ou vazia. O tamanho da justificativa é do schema.
    public CancelamentoSubstituicao(ChaveAcesso chave, string protocolo, string justificativa, ChaveAcesso chaveSubstituta);
    public string Protocolo { get; }
    public string Justificativa { get; }
    public ChaveAcesso ChaveSubstituta { get; }            // chNFeRef
    /// verAplic do detEvento (1 a 20 caracteres): a versão do aplicativo que emite. Padrão: "OpenDFe " + a versão do pacote,
    /// cortada em 20. Quem usa troca pela do seu sistema.
    public string VersaoAplicativo { get; init; }
}
```

   O `detEvento`: `descEvento` ("Cancelamento por substituicao", exatamente como o schema enumera), `cOrgaoAutor` (a UF da chave), `tpAutor` 1 (empresa emitente), `verAplic`, `nProt`, `xJust`, `chNFeRef`. Sequência sempre 1. Autor: o emitente da chave (como o cancelamento). Vai ao autorizador da chave **só quando a nota é da emissão normal** (o 920 e o 921 do emulador/MOC dizem que a substituição é da emissão normal): o tipo de evento **não** aceita a contingência SVC (a decisão 5 da 6.1: só o cancelamento comum aceita), então vai ao autorizador normal da UF. Registre no `retEvento` o `cOrgaoAutor` quando vier (o `ResultadoEvento` da 6.1 não tem o campo e **não ganha**: o `XmlProcessado` o carrega). O `procEventoNFe` desse evento passa no `procEventoNFe_v1.00.xsd`; o `retConsSitNFe_v4.00` do PL_010d diverge (veja `SEFAZ_EMULADA.md`, "Divergência entre os schemas do Portal"): não valide a resposta da consulta pelo schema neste caso, e documente.

2. **`CartaCorrecao`:**

```csharp
/// A carta de correção (110110) de uma NF-e (a NFC-e não tem). O texto da condição de uso é fixo (o schema o enumera).
public sealed class CartaCorrecao : Evento
{
    /// ArgumentNullException: chave nula. ArgumentException: chave que não é de NF-e (modelo 55), correção nula ou vazia.
    /// ArgumentOutOfRangeException: sequência fora de 1 a 20. O tamanho da correção (15 a 1000) é do schema.
    public CartaCorrecao(ChaveAcesso chave, int sequencia, string correcao);
    public string Correcao { get; }
}
```

   O `detEvento`: `descEvento` ("Carta de Correcao"), `xCorrecao`, `xCondUso` com o texto exato do `e110110_v1.00.xsd`. **A constante do texto tem teste que lê o XSD embutido e compara com a enumeração** (se uma NT mudar o texto, o teste acusa). Ela vai ao autorizador normal da UF (a SVC não registra CC-e). O `Sequencia` é de quem usa (a lib não sabe qual é a próxima): o guia explica (conte as CC-e da consulta).

3. **Sem regra nova fora do schema.** As verificações dos construtores (modelo da chave, chaves iguais, sequência, tamanho do protocolo) são validação de argumento, não regra do MOC. O resto (prazos, sequência acima do registrado, a substituta que não confere, a nota cancelada) fica para a SEFAZ. A `NFE-CHAVE` e a `NFE-LOTE` da 6.1 já cobrem o modelo diferente do do núcleo e os destinos misturados (CC-e e cancelamento da mesma nota no mesmo lote vão ao mesmo destino: ok).

4. **Um guia para quem usa:** `docs/EVENTOS.md`, com o código de cada caso: cancelar (e o prazo de 24 horas), cancelar por substituição (a NFC-e substituta já autorizada, a janela de 168 horas), corrigir (a sequência, o que a CC-e pode e não pode corrigir, em linguagem simples e com a referência ao MOC), inutilizar (quando, a faixa, a justificativa), os resultados (`Registrado`, `XmlProcessado`, o que guardar), a queda no meio (remeta ao `QUANDO_CAI.md`). Curto e com exemplos que compilam (confira os trechos num teste de documentação, ou ao menos escreva-os iguais aos do teste do emulador).
