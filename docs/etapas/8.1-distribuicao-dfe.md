# Etapa 8.1: distribuição DF-e

**Situação:** feita em 2026-10-24, commit 374ce0d.

**Branch:** `fase-8-distribuicao` (criar a partir da `fase-7-impressao`, seção 2.4 do `00-COMUM.md`). **Pré-requisito:** a 7.4 feita e commitada. **Regras comuns:** `docs/etapas/00-COMUM.md`.

**Objetivo:** consultar o `NFeDistribuicaoDFe` do Ambiente Nacional (por último NSU, por NSU e por chave) e devolver os documentos já descompactados (resumo da NF-e, NF-e processada, resumo de evento, evento processado), como a caixa de entrada do ErpCore precisa. Exige uma **mudança pequena no núcleo**: o `nfeDadosMsg` desse serviço vai dentro do elemento da operação (`nfeDistDFeInteresse`), e a resposta vem em `nfeDistDFeInteresseResult` (decisão da 4.2, `docs/NTS.md` 3.2).

**Aprovado em 2026-10-24, todas as decisões abaixo pela recomendação.** Registre em `docs/CONTRATOS.md` **24** (próximo número livre) o desenho como implementado.

## Decisões (todas aprovadas pela recomendação)

1. **Núcleo, o mínimo (API pública nova):** `ServicoSoap` ganha `public string? Operacao { get; init; }` ("quando não nulo, o `nfeDadosMsg` vai dentro de `<Operacao xmlns="namespaceWsdl">`, e a resposta é lida em `<Operacao>Response/<Operacao>Result`, em vez do `nfeResultMsg` direto no `Body`"). `EnvelopeSoap.Montar(servico, mensagem)` e `Ler(resposta, servico)` honram isso (a leitura continua tolerante com o namespace). Os serviços sem `Operacao` não mudam **um byte**: teste de regressão do envelope atual. Entra no `PublicAPI.Unshipped.txt` do núcleo, em `Nucleo.Testes` (`EnvelopeSoapTestes`, `TransporteSoapTestes` pelo servidor local), e na documentação de `CONTRATOS.md` 2.4.
2. **Declaração no leiaute (só a NF-e):** o serviço `NFeDistribuicaoDFe` com namespace `http://www.portalfiscal.inf.br/nfe/wsdl/NFeDistribuicaoDFe`, ação `.../NFeDistribuicaoDFe/nfeDistDFeInteresse`, `Operacao = "nfeDistDFeInteresse"`, e as URLs do **AN** nos dois ambientes (confirme na "Relação de Serviços Web" do Portal Nacional, seção Ambiente Nacional; as URLs conhecidas são `https://www1.nfe.fazenda.gov.br/NFeDistribuicaoDFe/NFeDistribuicaoDFe.asmx` e `https://hom1.nfe.fazenda.gov.br/NFeDistribuicaoDFe/NFeDistribuicaoDFe.asmx`, **mas confirme na fonte e registre em `docs/NTS.md` 3**). A NFC-e não é distribuída: o parâmetro só é registrado para `Documento.NFe`. Atualize `NTS.md` 3.2 (a linha "Fora: a distribuição DF-e...").
3. **O parâmetro:**

```csharp
/// A consulta à distribuição de DF-e do Ambiente Nacional (NFeDistribuicaoDFe, NT 2014.002). Sempre ao AN.
public sealed class DistribuicaoDFe : ParametroWS<RetornoDistribuicao>
{
    /// Os documentos a partir do NSU seguinte ao informado (0 na primeira vez). ArgumentException: interessado inválido; NSU negativo ou acima de 15 dígitos.
    public static DistribuicaoDFe UltimoNsu(string interessado, long ultimoNsu = 0);
    /// O documento de um NSU (consulta pontual; conta no limite de 20 por hora).
    public static DistribuicaoDFe Nsu(string interessado, long nsu);
    /// O documento de uma chave (consulta pontual; conta no limite de 20 por hora).
    public static DistribuicaoDFe Chave(string interessado, ChaveAcesso chave);

    public string Interessado { get; }               // o CNPJ ou o CPF, só os dígitos/letras
    public TipoConsultaDistribuicao Consulta { get; } // UltimoNsu, Nsu, Chave
    public long? NsuConsultado { get; }  public ChaveAcesso? ChaveConsultada { get; }
    /// cUFAutor; null = a UF do núcleo.
    public UF? UFAutor { get; init; }
}
public enum TipoConsultaDistribuicao { UltimoNsu, Nsu, Chave }
```

   `interessado` aceita máscara e é validado com `Cnpj.Valido`/`Cpf.Valido` (o do núcleo; o CNPJ alfanumérico incluído); vai ao XML sem máscara (`<CNPJ>` ou `<CPF>`). O `ultNSU`/`NSU` vai com 15 dígitos (zeros à esquerda). O pedido: `distDFeInt versao="1.01"` com `tpAmb` do núcleo, `cUFAutor`, o documento e a consulta; **sem assinatura**; destino **AN** e tipo de emissão normal; schema `distDFeInt_v1.01.xsd` (código 215).
4. **O retorno:**

```csharp
public sealed class RetornoDistribuicao                // construtor interno; imutável
{
    public int Status { get; }                         // 137, 138, 656 e as rejeições
    public string Motivo { get; }
    public Ambiente? Ambiente { get; }  public string? VersaoAplicativo { get; }
    public DateTimeOffset? Resposta { get; }           // dhResp
    public long? UltimoNsu { get; }  public long? MaximoNsu { get; }
    public IReadOnlyList<DocumentoDistribuido> Documentos { get; }   // vazia sem documento
    public bool NenhumDocumento { get; }               // 137
    public bool ConsumoIndevido { get; }               // 656
    /// Há mais a buscar: 138 com UltimoNsu menor que MaximoNsu. Chame de novo na hora, com o UltimoNsu devolvido.
    public bool TemMais { get; }
    /// A espera que a NT manda antes da próxima consulta: 1 hora no 137 e no 656; nula nos outros. (A lib não espera: é de quem usa.)
    public TimeSpan? EsperaSugerida { get; }
}

public sealed class DocumentoDistribuido               // construtor interno; imutável
{
    public long? Nsu { get; }                          // null na consulta por chave (o NSU é facultativo no docZip)
    public string Schema { get; }                      // "resNFe_v1.01.xsd", "procNFe_v4.00.xsd", ...
    public TipoDocumentoDistribuido Tipo { get; }
    public string Xml { get; }                         // descompactado (gzip), UTF-8, como veio
    public ChaveAcesso? Chave { get; }                 // lida do XML quando possível
    public ResumoNFe? ResumoNFe { get; }               // só no Tipo ResumoNFe
    public ResumoEvento? ResumoEvento { get; }         // só no Tipo ResumoEvento
}
public enum TipoDocumentoDistribuido { ResumoNFe, NFeProcessada, ResumoEvento, EventoProcessado, Outro }

public sealed class ResumoNFe       // resNFe: Chave, Emitente (CNPJ ou CPF), NomeEmitente, InscricaoEstadual, Emissao (dhEmi), TipoNota (tpNF), ValorTotal (vNF), Digest (digVal), Recebimento (dhRecbto), Protocolo (nProt), Situacao (cSitNFe)
public sealed class ResumoEvento    // resEvento: Orgao, Autor (CNPJ ou CPF), Chave, Momento (dhEvento), Tipo (tpEvento, o TipoEvento da 6.1 quando conhecido, senão o número), Sequencia, Descricao (xEvento), Recebimento (dhRecbto), Protocolo (nProt)
```

   Os tipos `ResumoNFe` e `ResumoEvento` são públicos, imutáveis, com propriedades tipadas nos tipos do modelo (`DateTimeOffset`, `decimal`, enumeração `SituacaoResumo` para `cSitNFe`: confira os valores no schema/NT, aberta como as outras). Para a NF-e processada e o evento processado, quem usa lê o `Xml` com `LeiauteNFe400.Ler` (a `NotaLida`) ou direto; **não duplique a leitura** da nota aqui. Documente.
5. **A leitura do `retDistDFeInt` é branda** (`LeituraRetorno`, `CONTRATOS.md` 13 decisão 4): o `docZip` é `base64` de `gzip`; cada `docZip` ilegível (base64 inválido, gzip corrompido, XML que não é bem formado) é **aviso `NFE-DISTRIBUICAO`** com o NSU, e o documento é omitido (os demais seguem). **Proteção contra bomba de descompressão:** descompacte com limite (16 MB por `docZip`; acima, aviso e omita). O `schema` desconhecido vira `Tipo.Outro`. `UltimoNsu` e `MaximoNsu` ilegíveis → nulos com aviso `NFE-VALOR`. A mensagem de resposta com mais de 50 `docZip` não é erro (a NT limita a 50; aceite o que vier).
6. **Sem regra fora do schema** (os argumentos são validados nos factories). **Sem automatismo** (8.6): a lib não repete a consulta, não espera, não guarda o NSU. O guia diz como.
7. **O guia `docs/DISTRIBUICAO.md`** (para o módulo fiscal do ErpCore e quem mais usar): o laço de sincronização com o código (guardar o `UltimoNsu`, chamar de novo enquanto `TemMais`, esperar `EsperaSugerida` no 137, nunca antes de 1 hora: o 656 bloqueia por 1 hora e recomeça a contagem), o primeiro acesso (NSU 0 traz os últimos 90 dias), o certificado (a raiz do CNPJ do interessado: a matriz consulta as filiais, 593/472), a consulta pontual (limite de 20 por hora), idempotência (o mesmo documento pode chegar de novo: grave pelo NSU/chave), a falha de transmissão (`PodeTerSidoProcessado` na distribuição é seguro repetir com o mesmo `UltimoNsu`, mas **cuidado com o 656**: se a consulta foi processada, a repetição com o mesmo `ultNSU` é o caso "outro ultNSU que não o último devolvido"? confirme na NT e escreva a recomendação exata), o que cada ator recebe (resumo antes da manifestação, `nfeProc` depois: a manifestação é a 8.2), e o exemplo de código completo.

- **Contra a SEFAZ emulada** (`DistribuicaoEmuladaTestes`; use **dois núcleos**, cada um com o seu certificado autoassinado de CNPJ diferente, via `CertificadoTeste { Cnpj = ... }`): o emitente A autoriza uma NF-e para o destinatário B (a lib monta e transmite); B consulta `UltimoNsu(B, 0)` → 138 com o `resNFe` (NSU 1) lido nos tipos; B consulta de novo com o `UltimoNsu` devolvido → 137; logo depois outro `UltimoNsu` → 656 (o uso indevido), com a `EsperaSugerida`; a nota com B no `autXML` (a lib escreve o `AutorizadosXml`) → B recebe o `nfeProc` na autorização (`NFeProcessada`, lido com `LeiauteNFe400.Ler` e igual à nota); o cancelamento (6.1) distribuído como `resEvento` e depois como `procEventoNFe`; `consNSU` e `consChNFe` (138, o `nfeProc` ou o `resNFe`; 217, 632, 640, 641, 653); o certificado de outro CNPJ (593); o ultNSU acima do máximo (589); a 21ª consulta pontual (656); o serviço paralisado (108/109); a conexão derrubada depois de processar e a repetição; paginação com mais de 50 documentos (autorize 55 notas para B e leia em dois lotes: `TemMais`).
