## Decisões (todas aprovadas pela recomendação)

1. **Onde ficam os tipos:** no `OpenDFe.NFe` (leiaute), como as da 4.4/4.5. O núcleo não muda (a assinatura por `Id`, `IdsAssinatura`, `Documentos` e o `Destino`/`Emissao` do `PedidoWS` já bastam). Se algo do núcleo atrapalhar, mude o mínimo e registre.
2. **A hierarquia, aberta só para a lib:**

```csharp
/// Um evento de um documento. A base é fechada: só o leiaute deriva (construtor private protected e membros internos).
public abstract class Evento
{
    private protected Evento();                       // cada subclasse valida os seus argumentos
    public ChaveAcesso Chave { get; }                 // chNFe
    public TipoEvento Tipo { get; }                   // tpEvento
    public int Sequencia { get; }                     // nSeqEvento (1 no cancelamento)
    /// dhEvento; null = o instante do relógio da configuração, no fuso de Brasília (-03:00).
    public DateTimeOffset? Momento { get; init; }
    // internos, que a subclasse implementa: Descricao (descEvento), Orgao(contexto) (cOrgao), Destino(contexto),
    // TipoEmissaoPedido, o detEvento escrito, o autor (CNPJ ou CPF), a propriedade do modelo de cada campo.
}

public enum TipoEvento
{
    CartaCorrecao = 110110, Cancelamento = 110111, CancelamentoSubstituicao = 110112,
    ConfirmacaoOperacao = 210200, CienciaOperacao = 210210, DesconhecimentoOperacao = 210220, OperacaoNaoRealizada = 210240,
}

/// O cancelamento (110111). O autor é o emitente da chave.
public sealed class Cancelamento : Evento
{
    /// ArgumentNullException: chave nula. ArgumentException: protocolo que não tem 15 dígitos; justificativa nula ou vazia.
    /// O tamanho da justificativa (15 a 255) e a pontuação são do schema (TJust), na montagem.
    public Cancelamento(ChaveAcesso chave, string protocolo, string justificativa);
    public string Protocolo { get; }                  // nProt da autorização (ResultadoNota.Protocolo.Numero)
    public string Justificativa { get; }
}
```

   Nomes sem preposição: o tipo da substituição é **`CancelamentoSubstituicao`** (o `PROJETO.md` 8.3/9.3 escreve `CancelamentoPorSubstituicao`, anterior à regra de nomes; atualize o texto do `PROJETO.md` e registre a divergência).

3. **O envio, o retorno e o resultado por evento:**

```csharp
public sealed class EnvioEvento : ParametroWS<RetornoEvento>
{
    public const int MaximoEventos = 20;
    /// ArgumentException: nenhum, mais de 20, ou um nulo.
    public EnvioEvento(params IEnumerable<Evento> eventos);
    public IReadOnlyList<Evento> Eventos { get; }
    /// O idLote (1 a 15 dígitos); null = do relógio da configuração (como a Autorizacao.Lote).
    public long? Lote { get; init; }
}

public sealed class RetornoEvento                    // construtor interno; imutável
{
    public int Status { get; }                       // cStat do lote: 128 (processado) ou a rejeição do lote
    public string Motivo { get; }
    public Ambiente? Ambiente { get; }
    public string? VersaoAplicativo { get; }
    public int? Orgao { get; }                       // cOrgao do retorno
    public long? Lote { get; }                       // idLote
    /// Um por evento enviado, na ordem do envio. Vazia na rejeição do lote.
    public IReadOnlyList<ResultadoEvento> Eventos { get; }
}

public sealed class ResultadoEvento                  // construtor interno; imutável
{
    public Evento? Evento { get; }                   // o enviado (ligado pela chave + tipo + sequência; senão pela posição)
    public ChaveAcesso? Chave { get; }
    public int Status { get; }                       // cStat do evento: 135, 136, 155 ou a rejeição
    public string Motivo { get; }
    public string? Descricao { get; }                // xEvento
    public string? Protocolo { get; }                // nProt do evento
    public DateTimeOffset? Registro { get; }         // dhRegEvento
    public string? XmlEvento { get; }                // o evento assinado, como foi enviado
    /// O procEventoNFe (o evento com os bytes enviados e o retEvento): só quando registrado. É o XML distribuível do evento.
    public string? XmlProcessado { get; }
    public bool Registrado { get; }                  // Status 135, 136 ou 155
}
```

   `Registrado`: 135 (registrado e vinculado), 136 (registrado, não vinculado: sai na manifestação sem a nota na base) e 155 (cancelamento homologado fora de prazo, a critério da UF). Confirme os três no MOC 7.0 e registre.

4. **A montagem:** o `envEvento` (`versao` 1.00, `idLote`, cada `evento` com `versao` 1.00); cada `infEvento` com `Id` = `"ID"` + `tpEvento` + chave (44) + `nSeqEvento` com 2 posições; `cOrgao` (a UF da chave; 91 no AN, para a 8.2); `tpAmb` do núcleo; `CNPJ` **ou** `CPF` do autor (no cancelamento, o documento do emitente tirado da chave: `chave.Emitente` tem 14 posições, os 11 últimos quando o documento é CPF com zeros à esquerda: veja como a `ChaveAcesso` guarda o CPF e como o emulador decide, `P10`/`P11`); `chNFe`; `dhEvento` (`FormatadorInvariavel.DataHora`, com o fuso); `tpEvento`; `nSeqEvento`; `verEvento` 1.00; `detEvento versao="1.00"` com o `descEvento` do tipo, o `nProt` e o `xJust`. `IdsAssinatura` = os `Id` dos `infEvento`, um por evento; um `DocumentoPedido` por evento (o `Id`, a chave, a propriedade `Eventos[k].`). O schema da mensagem é o `envEvento_v1.00.xsd`; o **`detEvento` de cada evento é validado na montagem pelo schema do tipo** (`e110111_v1.00.xsd` para o cancelamento), com o código **493** (o da SEFAZ para detalhe inválido) e a propriedade do campo (`Eventos[0].Justificativa`): o `detEvento` é um elemento global desses XSDs, então valide o fragmento escrito (com o namespace) num `SchemaXml` próprio (`SchemaXml.Carregar`, com o mapa tag→propriedade). Isso põe o limite da justificativa onde o repositório o põe (o schema), não no construtor.
5. **O destino e o tipo de emissão** (`PROJETO.md` 8.4, como a 4.5): saem da **chave** (`chave.UF.ComoDestino()` e `chave.TipoEmissao`), e o `Destino` do parâmetro sobrepõe, indo ao autorizador normal com o tipo de emissão normal (o ajuste da 4.5, `CONTRATOS.md` 15.6). **Exceção por tipo de evento:** só o **cancelamento** pode ir à SVC (a SVC registra só o 110111, e só das notas que ela autorizou: Anexo III, 2.1.3, c e d). Os outros tipos, mesmo numa chave de SVC, vão ao autorizador normal da UF com o tipo de emissão normal. Implemente como um membro interno do evento (por exemplo, `AceitaContingencia`), para a 6.2 e a 8.2 não mudarem o `OperacaoEvento`.
6. **O `procEventoNFe`:** monta-se com o `evento` **como foi enviado, com os bytes assinados** (tire-o do `xmlPedido` como o `LoteNFe` tira as notas: sem o BOM e a declaração, sem reescrever) e o `retEvento` da resposta (relido pelo `XElement`, equivalente e não byte a byte, como o `protNFe` do `nfeProc` e os eventos da consulta da 4.5). Valide o `procEventoNFe` produzido contra o `procEventoNFe_v1.00.xsd` nos testes. Atenção ao achado do `SEFAZ_EMULADA.md`: o `retEvento` do cancelamento por substituição traz o `cOrgaoAutor`, que o `procEventoNFe_v1.00` prevê (a 6.2 usa).
7. **A leitura do retorno** é branda (`LeituraRetorno`, `CONTRATOS.md` 13 decisão 4): o `retEnvEvento` com os `retEvento` ligados aos eventos enviados pela chave + `tpEvento` + `nSeqEvento`; se um `retEvento` vier sem esses campos (rejeição que não chegou a lê-los), liga-se pela posição quando a quantidade de `retEvento` é igual à de eventos enviados; o que sobrar vira `ResultadoEvento` com `Evento` nulo e o aviso `NFE-EVENTO`. Lote rejeitado (`cStat` ≠ 128) devolve `Eventos` vazio. Avisos `NFE-VALOR`, `NFE-DESCONHECIDO`, `NFE-REPETIDO` como no status e na autorização.
8. **A inutilização:**

```csharp
public sealed class Inutilizacao : ParametroWS<RetornoInutilizacao>
{
    /// cnpj: o do emitente (com ou sem máscara). ArgumentException: CNPJ inválido, série fora de 0 a 999, número
    /// inicial menor que 1, final menor que o inicial, justificativa nula. O tamanho da justificativa (15 a 255) é do schema.
    /// O emitente com CPF não tem inutilização neste schema (infInut só tem CNPJ): fica pendente, registre.
    public Inutilizacao(string cnpj, int serie, int numeroInicial, int numeroFinal, string justificativa);
    /// O ano com 2 dígitos (a numeração é do ano); null = o ano do relógio, no fuso de Brasília.
    public int? Ano { get; init; }
    public string Cnpj { get; }  public int Serie { get; }  public int NumeroInicial { get; }  public int NumeroFinal { get; }
    public string Justificativa { get; }
}

public sealed class RetornoInutilizacao              // construtor interno; imutável
{
    public int Status { get; }                       // 102 (homologada), 563 (já inutilizada) ou a rejeição
    public string Motivo { get; }
    public Ambiente? Ambiente { get; }  public string? VersaoAplicativo { get; }  public UF? UF { get; }
    public int? Ano { get; }  public string? Cnpj { get; }  public Documento? Modelo { get; }  public int? Serie { get; }
    public int? NumeroInicial { get; }  public int? NumeroFinal { get; }
    public DateTimeOffset? Recebimento { get; }  public string? Protocolo { get; }
    /// O procInutNFe (o inutNFe com os bytes enviados e o retInutNFe): só quando homologada (102).
    public string? XmlProcessado { get; }
    public bool Homologada { get; }                  // Status 102
}
```

   O pedido: `inutNFe versao="4.00"` com `infInut Id="ID"+cUF+ano+CNPJ+mod+serie(3)+nNFIni(9)+nNFFin(9)`, `tpAmb`, `xServ` `INUTILIZAR`, `cUF` (a do núcleo), `ano`, `CNPJ`, `mod` (55 ou 65, pelo documento do núcleo), `serie`, `nNFIni`, `nNFFin`, `xJust`; `IdsAssinatura` = o `Id` do `infInut`. **Sempre ao autorizador normal da UF do núcleo, com tipo de emissão normal**, mesmo que o núcleo esteja em contingência (a SVC não oferece a inutilização). O schema é o `SchemasNFe400.Inutilizacao`. Para o `procInutNFe`, confira no `procInutNFe_v4.00.xsd` o nome exato do elemento raiz e da `versao`.
9. **Regras fora do schema (aprovadas):**

   | Regra | Código | Severidade | O que confere |
   |---|---|---|---|
   | (lib) | `NFE-CHAVE` | Erro | A chave de um evento é de outro modelo que o do núcleo (NFC-e num núcleo de NF-e e o contrário), como a 4.5. |
   | (lib) | `NFE-LOTE` | Erro | No mesmo `EnvioEvento`: eventos que iriam a destinos ou tipos de emissão diferentes (a SEFAZ processa o lote por um órgão só, R06), ou o mesmo evento repetido (mesmo `tpEvento`, chave e `nSeqEvento`, que seria o 573). |

   São problemas da montagem (códigos novos em `CodigosEscrita.cs`, linhas no `REGRAS.md`). **Nenhuma outra**: o prazo do cancelamento (501), a sequência, o titular do certificado contra o autor (213, 227, 574) e a situação da nota ficam para a SEFAZ.
10. **A NFC-e:** o `EnvioEvento` e a `Inutilizacao` são registrados nos dois documentos (`Declarar`), com o mesmo código da NF-e.
11. **Sem automatismo** (8.6): a lib não repete o evento nem consulta sozinha. A queda no meio de um cancelamento se resolve pela `ConsultaProtocolo` (101 = cancelada; os eventos vêm no `RetornoProtocolo.Eventos`); acrescente a seção "Cancelamento e inutilização" ao `docs/QUANDO_CAI.md`, com o código: resposta perdida do cancelamento → consultar a chave → 101 já cancelada (o `procEventoNFe` está nos eventos da consulta) ou 100 → reenviar o mesmo evento (o mesmo `Momento`, para os mesmos bytes e o mesmo `Id`; o 573 diz que já foi registrado); inutilização perdida → reenviar (563 diz que já foi, com a faixa e o `nProt`).
12. **`RetornoProtocolo.Eventos` continua texto** (a 4.5 deixou "o evento tipado vem na fase 6"): **não mude**. Registre na situação que a tipagem fica para uma versão menor futura, e que quem usa lê o `procEventoNFe` pelo XML (a leitura tipada do evento registrado não está no escopo da fase 6).
